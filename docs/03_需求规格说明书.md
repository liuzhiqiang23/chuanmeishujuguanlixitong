# 《电影票房预测与智能推荐系统》需求规格说明书（细化版）

> 课程作业 · 第五步 ①　|　上游文档：`docs/01_需求分析.md`（第三步）
> 本文档在第三步需求分析的基础上**细化到可验收**：每条功能需求给出输入、处理、输出与验收判据，并明确与"框架保留功能"的边界。

## 1. 范围与边界

### 1.1 系统范围

本系统以 `movie-system`（Spring Boot + Vue3 管理后台 + 微信小程序 + Python 算法引擎）为**框架**，替换数据集与算法内核，形成新项目：

- **新做**（新项目本体）：数据导入与影片库检索、探索性分析（EDA）、票房预测（单片/批量）、多算法对比、智能推荐——数据来自新数据集 `data/train.csv` / `data/test.csv` 与新建数据库 `movie_analytics_db`。
- **保留**（框架功能，不属于新项目，但必须继续可用）：登录与权限、用户/角色/日志/消息管理、影片管理（海报、播放）、小程序商城（会员/优惠券/订单）、小程序端页面。

### 1.2 术语

| 术语 | 含义 |
|---|---|
| 新数据集 | Kaggle The Movies Dataset 合并去重后固定种子抽样：train 5000 行、test 5000 行 |
| 对数票房 | `log10(revenue)`，模型实际拟合的目标量 |
| 最佳模型 | 8 种算法对比中验证集 RMSE 最小者（当前为随机森林） |
| 新库 | `movie_analytics_db`，第四步新建（15 张业务表） |
| 旧库 | `vidio_mangage_db`，老师原电影系统数据库（框架表来源） |

## 2. 用户角色

| 角色 | 权限 | 主要场景 |
|---|---|---|
| 管理员（role=3） | 全部功能 | 导入数据、训练/对比模型、看预测与推荐结果、维护影片 |
| 数据分析人员（登录用户） | 分析类功能 | 看 EDA 图、用票房预测评估影片 |
| 普通用户（小程序） | 浏览与购买 | 浏览影片、看推荐、买会员/领券 |

> 沿用框架的角色体系，不新增角色，仅新增功能入口（新项目页面挂在管理员与登录用户可见的菜单下）。

## 3. 功能需求（细化）

### FR1 影片数据入库与检索

| 项 | 内容 |
|---|---|
| 输入 | `data/processed/train_clean.csv`（5000×48）、`test_clean.csv`（5000×46） |
| 处理 | 导入脚本解析：电影主表（t_movie）+ 类型/关键词/公司/国家字典与关联表 + 演职员（t_person/t_movie_cast/t_movie_crew）；重复导入按 id 幂等更新 |
| 输出 | 新库各表有数据；接口返回分页影片列表、单部详情（含类型、关键词、前 10 主演、导演） |
| 验收判据 | ① 导入后 `t_movie` 行数 = 10000（train+test）；② 详情接口对任意 id 能返回关联的类型/演员（非空）；③ 按类型/关键词/年份区间筛选结果条数正确 |

### FR2 探索性数据分析（EDA）

| 项 | 内容 |
|---|---|
| 输入 | `data/processed/*_clean.csv` |
| 处理 | `algorithm/FeatureEDA/eda.py` 一次生成 21 张图（fig01~fig14 多维分析 + 7 张网页固定图）；后端 `/eda/**` 直读图片目录 |
| 输出 | 网页「特征探索分析」9+21 张图，含大图预览；重跑脚本后刷新页面即见新图 |
| 验收判据 | ① 21 张 PNG 全部可访问（HTTP 200）；② 页面无"图片缺失"占位；③ 重跑 `eda.py` 不改前端代码即生效 |

### FR3 票房预测（单片）

| 项 | 内容 |
|---|---|
| 输入 | 表单：预算、热度、时长、语言、上映状态、类型（可选）等；或从影片库选一部自动填充其真实特征 |
| 处理 | 后端 → Python 推理服务（加载最佳模型 joblib）→ 输出 `log10` 预测值并还原为美元 |
| 输出 | 预测票房（美元，含千分位与"亿美元"换算）、参考区间、所用模型名 |
| 验收判据 | ① 合法输入返回 code=1 与预测值 > 0；② 预算为空/负数返回可读错误提示（非 500 堆栈）；③ 同一输入两次调用结果一致（模型确定性） |

### FR4 批量预测与留痕

| 项 | 内容 |
|---|---|
| 输入 | `data/test.csv` 中的 N 条影片（默认 1000 条，可指定） |
| 处理 | 批量推理 → 每条结果写入 `t_prediction_log`（影片 id、预测值、模型、时间） |
| 输出 | 进度与汇总（条数、耗时、预测票房分布）；结果可查、可导出 CSV |
| 验收判据 | ① 1000 条批量预测 < 60s；② `t_prediction_log` 新增行数 = 条数；③ 导出文件列名与界面一致 |

### FR5 多算法对比

| 项 | 内容 |
|---|---|
| 输入 | `data/processed/train_clean.csv` |
| 处理 | `algorithm/boxoffice_prediction/train_all.py` 训练 **8 种算法**（线性回归、决策树、随机森林、梯度提升、KNN、SVR、MLP 深度学习、LightGBM），8:2 切分，seed=42 |
| 输出 | `metrics.json`（RMSE/MAE/R²/耗时 + 最佳模型标记）、`algo_comparison.png` 对比图、`best_model.joblib` |
| 验收判据 | ① 算法数 ≥ 6（实际 8，含 1 种深度学习）；② 指标表按 RMSE 升序、最佳行高亮；③ 对比图可在线查看；④ 重跑结果与 `metrics.json` 一致（随机种子固定） |

### FR6 智能推荐

| 项 | 内容 |
|---|---|
| 输入 | 一部种子影片（或一种类型/关键词） |
| 处理 | 基于**新数据集**的内容相似推荐：类型、关键词、演职员、公司/国家、热度与评分人数加权 → 余弦相似度排序；不依赖已删除的 MovieLens 评分数据 |
| 输出 | Top-N 推荐列表（影片名、海报、相似度、可读理由如"同类型：动画/冒险；同导演"） |
| 验收判据 | ① 任意合法种子影片返回 N 条且不含自身；② 每条附推荐理由；③ 结果可复现（同一输入结果一致） |

### FR7 系统管理（框架保留，不改造）

登录鉴权、用户/角色、日志、消息、影片管理、小程序商城等维持原功能；本期只做数据库迁移后的回归验证。

| 验收判据 | 迁移到新库后：① 管理员与演示账号均可登录；② 影片列表、日志、消息、会员/优惠券接口返回正常；③ 小程序端主要页面数据正常 |

### FR8 数据库与数据管理

| 项 | 内容 |
|---|---|
| 处理 | 新库 `movie_analytics_db` 作为系统唯一库：15 张新项目表（第四步已建）+ 框架表由旧库迁入；旧库在迁移验证通过后删除 |
| 验收判据 | ① 新库表数 ≥ 8（实际 15 张业务表 + 框架表）；② 应用配置指向新库后全功能可用；③ 旧库删除前已留有完整备份文件 |

## 4. 非功能需求（细化）

| 类别 | 指标 | 验证方式 |
|---|---|---|
| 性能 | 单片预测接口 < 500ms（不含 Python 冷启动，首次 < 3s）；批量 1000 条 < 60s | 计时打印/日志 |
| 可复现 | 训练与推荐均固定 seed=42，同数据同结果 | 连续两次运行的 metrics 完全一致 |
| 可移植 | 所有路径相对 `backend` 目录；拷贝整个工程到任意盘符无需改配置 | 换目录启动一次 |
| 可靠 | Python 调用超时（预测 20s / 推荐 30s）与异常兜底，返回可读错误而非 500 堆栈 | 故意改错脚本路径验证 |
| 安全 | DB 密码与 RSA 私钥走环境变量（`local_env.cmd`，不入库）；接口鉴权沿用 token 拦截器 | `git status` 无密钥文件；未登录调用受保护接口返回 401 |
| 可维护 | 算法与后端解耦：算法脚本 JSON 进出，后端只负责调度 | 手工命令行跑通同一脚本 |

## 5. 数据需求

### 5.1 数据集字段（关键）

| 字段 | 类型 | 用途 |
|---|---|---|
| id / imdb_id | 文本 | 主键与外部标识 |
| budget / revenue | 数值 | 预算；票房（**仅 train 有**） |
| popularity / vote_average / vote_count | 数值 | 热度与口碑（vote_count 与票房相关 0.79，最强单特征） |
| genres / keywords / production_companies / production_countries / spoken_languages | JSON 文本 | 多值属性 → 关联表 |
| cast / crew | JSON 文本 | 演职员 → 人员表 |
| release_date / runtime / original_language / status | 文本/数值 | 时间与规格特征 |
| belongs_to_collection | JSON/空 | 系列片标志 |

### 5.2 派生特征（34 维模型输入）

16 个数值/布尔：log_budget、has_budget、runtime、cast_size、log_popularity、log1p(vote_count)、vote_average、n_genres、n_keywords、n_countries、n_companies、n_languages、is_collection、is_english、year、month；
18 个独热：main_genre（Top10）、main_country（Top6）、language 等。

## 7. 验收标准汇总（第五步末自检用）

1. 需求条目 FR1~FR8 均可映射到"输入—处理—输出—判据"，无"待定"项；
2. 每条功能需求都有**可执行**的验收判据（可手工验证，不依赖主观判断）；
3. 接口清单与详细设计的接口契约一一对应，命名、参数、返回结构一致；
4. 数据库设计满足"≥8 张表"且每张表能追溯到需求（不建无用表）；
5. 已识别风险（数据偏差、类别长尾、环境差异、旧库迁移）均有对策。

## 8. 约束与假设

- 运行环境：Windows + JDK 21 + Maven 3.9 + MySQL 8 + Redis（Memurai）+ Python 3.13 虚拟环境（`.venv`）；
- 预测模型为**离线训练、在线加载**：预测不重新训练，保证接口响应速度；
- train 抽样限定 `revenue > 0`，模型规律来自"已上映且有票房记录"的影片，对未上映影片外推需在界面提示；
- 深度学习部分采用 scikit-learn MLP（不引入重型框架），保证同学机器可复现；
- 小程序端不在本期改造范围（框架保留），仅做数据回归验证。
