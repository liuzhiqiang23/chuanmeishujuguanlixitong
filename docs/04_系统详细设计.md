## 3. 数据库详细设计

### 3.1 命名冲突与处理（审查发现）

新库 15 张表与框架 19 张表中，**只有 `t_user` 重名**（新项目"用户"用于评分；框架"用户"用于登录鉴权，字段完全不同）。处理：

- 新项目表改名 `t_user` → **`t_movie_user`**（`sql/movie_analytics_db.sql` 同步修改，语义：站内评分用户）；
- `t_rating.user_id` 指向 `t_movie_user.id`；
- 框架登录表 `t_user` 保持原名不动，框架代码零改动。

### 3.2 新项目表（15 张，第四步交付，此处补充字段说明与用法）

| # | 表 | 关键字段 | 系统内用法 |
|---|---|---|---|
| 1 | t_movie | id(TMDB), video_name, original_title, overview, release_date, year, month, runtime, budget, revenue, log_budget, log_revenue, popularity, vote_average, vote_count, original_language, status, poster_path, is_collection | 影片库检索/详情；预测页取真实特征；训练数据来源 |
| 2 | t_genre / 3. t_movie_genre | name；movie_id+genre_id | 类型筛选、类型分布大盘、推荐特征 |
| 4 | t_person / 5. t_movie_cast / 6. t_movie_crew | name；movie_id+person_id+character_name+cast_order；department+job | 详情页演职员、推荐理由（同导演/同主演） |
| 7 | t_keyword / 8. t_movie_keyword | name；movie_id+keyword_id | 详情页关键词、推荐特征 |
| 9 | t_company / 10. t_movie_company | name；movie_id+company_id | 详情页公司、推荐特征 |
| 11 | t_country / 12. t_movie_country | iso_code+name；movie_id+country_id | 详情页国家、推荐特征 |
| 13 | t_movie_user | username, password(RSA), nickname, role | 站内评分用户（邮箱化扩展位） |
| 14 | t_rating | user_id, movie_id, score 0.5~10, comment | 推荐策略 C 的信号源（可空） |
| 15 | t_prediction_log | movie_id, model_name, input_features(JSON), predicted_log_revenue, predicted_revenue | 批量/单片预测留痕，供结果查询与审计 |

**索引要点**：`t_movie` 已有 idx_year / idx_revenue / idx_name；检索页常用"类型 + 年份区间 + 热度排序"，靠 `t_movie_genre.idx_genre` + `t_movie.idx_year` 组合过滤，数据量 1 万行无需额外索引。

### 3.3 框架表迁入方案（第六步执行，先备份后切换）

| 步骤 | 命令/动作 | 验证 |
|---|---|---|

| 2 | 将 dump 导入 `movie_analytics_db`（表名不变，仅库名不同） | `SHOW TABLES` 两库表名并集一致，行数抽样比对 |

| 4 | 回归验证：登录、影片列表、日志、消息、会员/优惠券、小程序主要接口 | 见 §9 验收清单 |
| 5 | 验证通过后 `DROP DATABASE vidio_mangage_db` | 旧库消失，备份文件留档 |

> 说明：迁入后 `movie_analytics_db` 同时容纳"新项目表 + 框架表"，满足第四步"删除与新项目无关的旧库"；表名零改动意味着框架的 MyBatis 映射与 SQL 无需修改，风险可控。

### 3.5 数据导入设计（`sql/import_movie_dataset.py`）

- 输入：`data/processed/train_clean.csv`（5000×48）、`test_clean.csv`（5000×46）；两者按 id 合并去重后入库，`revenue` 仅 train 有（test 记 0 并在 `t_prediction_log` 侧区分）。
- 解析：`genres/keywords/production_companies/production_countries` 为 JSON 文本 → 字典表 upsert + 关联表插入；`cast/crew` 取 cast 前 10 与 crew 中 `job='Director'` 入库（控制数据量）。
- 幂等：`INSERT ... ON DUPLICATE KEY UPDATE`；先清后插仅限关联表（`DELETE FROM t_movie_cast WHERE movie_id=?` 再插）。
- 输出：控制台进度 + 各表行数汇总；预期 `t_movie` = 10000 行，`t_genre` ≲ 20，`t_person` ≲ 6 万。
- 编码：连接串 `charset=utf8mb4`；脚本用 `pymysql`/`mysql-connector`（requirements 已有则复用）。

## 4. 算法引擎详细设计

### 4.1 统一调用契约（后端 ↔ Python）

沿用框架既有约定，保证第六步只换脚本不换调度代码：

```
调用：<python.exe> <脚本> --arg1 v1 --arg2 v2 ...
约定：UTF-8 输出；stdout 最后一行非空文本必须是 JSON 对象；
     成功 {"ok":true, ...业务字段}；失败 {"error":"可读原因"}
```

### 4.2 票房推理服务 `algorithm/boxoffice_prediction/predict_api.py`（第六步）

| 项 | 设计 |
|---|---|
| 依赖物 | `models/best_model.joblib` + `models/feature_meta.json`（特征列顺序、类别取值表、log 变换参数）；训练脚本 `train_all.py` 一并导出 |
| 入参 | `--model rf|best`、`--budget`、`--popularity`、`--runtime`、`--language`、`--status`、可选 `--genres`、`--release-month` |
| 处理 | 构造 34 维特征（缺省值：预算缺失→has_budget=0 且 log_budget 取训练中位数；其余按 §2.3 规则）→ 预测 log10 票房 → 还原美元 |
| 出参 | `{"ok":true,"model":"RandomForest","log_revenue":8.12,"prediction":131825673,"currency":"USD","range":{"low":…,"high":…},"metrics":{"rmse":0.875,"mae":0.5546,"r2":0.591},"trainedNow":false}` |
| 区间 | `range = 10^(ŷ ± 1.96·RMSE)`（对数正态近似），前端以"参考区间"展示，不做强承诺 |
| 批量 | `--batch <csv> --limit N`：逐行推理，每 200 条输出一行进度到 stderr（stdout 最后一行仍为汇总 JSON） |

### 4.3 推荐引擎 `algorithm/movie_recommendation/recommend_api.py`（第六步）

数据源为**新数据集**（不含已删除的 MovieLens），三种策略可组合：

| 策略 | 参数 | 相似度/排序 |
|---|---|---|
| A 相似影片（主） | `--movie <id>` | 特征向量 = [类型 one-hot ×2.0, 关键词 TF-IDF ×1.0, 导演 ×1.5, 前 3 主演 ×1.2, 公司 ×0.8, 国家 ×0.8, 语言 ×0.5]，余弦相似度 Top-N |
| B 类型热门 | `--genre <name>` | 同类型内按 `0.6·z(popularity)+0.4·z(log1p(vote_count))` 排序 |
| C 评分加权（可选） | `--user <id>` | 取 `t_rating` 中该用户评分 ≥7 的影片，把其类型频次作为加权项叠加到 A/B 的排序得分上；无评分时自动跳过 |

出参：`{"ok":true,"strategy":"similar","items":[{"movieId":862,"title":"玩具总动员","posterPath":"…","score":0.83,"reasons":["同类型：动画/冒险","同导演：John Lasseter"]}]}`

### 4.4 训练（已实现，此处仅登记契约）

`train_all.py` 输出物新增一项以支持在线推理：`models/feature_meta.json`（第六步补导，不重训模型）。

## 7. 关键流程

**单片预测**：页面表单 → 校验 → `POST /api/predict` → `PredictServiceImpl` 组装参数 → ProcessBuilder 调 `predict_api.py` → stdout JSON → 组装 `PredictResultVM` → 页面渲染预测值/区间/模型指标。

**批量预测**：页面选条数 → `POST /api/predict/batch` → 服务端调 `predict_api.py --batch data/processed/test_clean.csv --limit N` → 逐条回传 JSON 行 → 批量写 `t_prediction_log` → 返回汇总。

**智能推荐**：页面选影片/类型 → `POST /api/recommend` → `RecommendServiceImpl` 调 `recommend_api.py` → 引擎内部读取新数据集特征（相似度矩阵离线缓存于 `algorithm/movie_recommendation/cache/`）→ 返回带理由的列表。

**数据导入**：`python sql/import_movie_dataset.py` → 解析清洗后 CSV → 幂等写入 15 张表 → 打印行数汇总（第六步一次性执行，纳入一键启动脚本的可选步骤）。

| 联调 | 端到端走一遍 | 预测页预测的影片能在详情页看到留痕；推荐页"看相似"能互相跳转 |
| 回归 | 框架功能抽查 | 登录/影片列表/日志/消息/商城/小程序接口正常 |
| 性能 | 批量 1000 条计时 | < 60s；单片 < 3s（含冷启动） |

## 10. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 预测区间被误读为承诺 | 体验/严谨性 | 界面标注"统计参考区间（±1.96·RMSE，对数正态近似）" |
| 类别长尾（类型/国家 独热截断） | 预测偏差 | 保留 Other 桶；文档说明 Top10/Top6 截断 |
| 推荐冷启动（无站内评分） | 策略 C 失效 | C 自动跳过，A/B 兜底（已在契约中体现） |
| 旧库迁移失败 | 系统不可用 | 先 dump 备份、再切换、后删库；三步之间有回归验证 |
| Python 环境差异（LightGBM 缺失） | 训练算法数 | 训练脚本自动降级为 7 种，仍满足"≥6 种" |
| 脚本路径相对 backend 目录 | 换机启动失败 | 全部相对路径 + 一键启动脚本固定工作目录 |
